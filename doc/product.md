# 製品概要 (product.md)

## 🌟 製品の目的
AIコーディングエージェントの自律実行において、「フロンティアモデルの賢さ」だけに頼るのではなく、**実行環境（ハーネス）側で状態や制約を担保するガードレール型タスク管理 MCP (Model Context Protocol) サーバー**を提供する。

エージェントが複雑な作業を進める中で発生しやすい「コンテキストドリフト（迷子）」、「タスクのすっ飛ばし・サボり」、「依存関係を無視した先行着手」、「勝手な完了扱い」を外部から厳格に制御し、軽量・低コストなモデル（Gemini Flash系やClaude Haiku系など）であっても高い完遂率と決定論的な実行順序を実現する。

## 🎯 ターゲットユーザー
- **自律型AIエージェント / コーディングエージェント**: Cursor, Claude Desktop, Antigravity, Cline, 自作CLIエージェントなどのMCPクライアント。
- **AIソフトウェアエンジニア / 開発者**: エージェントのタスク消化の透明性と制御性を向上させ、安定した自動コーディング環境を構築したい開発者。

## ✨ 主要機能 (Core Features)
- **迷わせない・トークンを圧迫しない極小ツールセット**:
  - `init_task_list(tasks)`: ゴールと分解されたサブタスク一覧（タスクID、タイトル、説明、依存先行タスクID）の初期登録
  - `get_current_task()`: いま着手すべき単一タスクの取得（次のアクションをモデルに迷わせない）
  - `update_task_status(id, status, notes)`: タスクステータス（`in_progress`, `completed`, `failed`, `paused`）の更新とメモの記録
  - `get_task_summary()`: 全体の進捗状況、タスクグラフ、未完了/完了タスク一覧の取得
- **ハーネスによるガードレール制約 (Guardrails)**:
  - **シングルアクティブ制約 (Single Active Constraint)**: 同時に `in_progress`（進行中）にできるタスクは**常に1つだけ**。別のタスクを始めるには、現在のタスクを `completed` または明示的に `paused` にしない限りエラーを返す。
  - **依存関係の強制 (Dependency Enforcement)**: 先行タスク（`depends_on`）が `completed` になっていない後続タスクへの着手（`in_progress` 化）をサーバー側バリデーションで拒否する。
- **透明性のあるローカル透過ストレージ**:
  - プロジェクトルートの `.agent/tasks.json`（またはMarkdown形式）に直接永続化。DBに隠蔽せず、人間がエディタで直接確認・手動修正でき、`git diff` でエージェントの作業軌跡を完全に追跡可能。
- **高速・堅牢なネイティブバイナリ**:
  - Rust言語で実装され、Node.jsやPythonランタイム不要の単一バイナリとしてミリ秒未満で起動し、省メモリで動作。

## 🚀 ビジネス目標 / ゴール
- **フロンティアモデル依存の低減**: 外部ハーネスが強固なレールを敷くことで、安価な軽量モデルでもタスク脱線や無限ループを防ぎ、タスク完遂率を大幅に向上させる。
- **高ポータビリティ**: MCP標準プロトコル（JSON-RPC 2.0 / stdio）に準拠し、任意のMCPクライアントからプラグアンドプレイで利用可能にする。
- **信頼性と検証性**: 状態遷移と依存関係チェックの決定論的テストカバレッジを確保し、壊れない作業状態管理基盤を提供する。

## ⚠️ 制約事項 / スコープ外
- **多機能ToDo管理機能の排除**: JiraやGitHub Projectsのような多機能プロジェクト管理ツール（担当者割り当て、期日カレンダー、ラベル分類、リッチUIなど）はスコープ外とし、エージェント実行制御に特化する。
- **リモートクラウド同期 / 認証**: リモートDBやSaaS同期、マルチユーザー同時編集競合解決は行わず、ローカルリポジトリ環境でのスタンドアロン動作に専念する。
- **外部依存重厚DBの不採用**: SQLiteや外部DBサーバーは使わず、シンプルなファイルベース（JSON）による永続化に留める。
